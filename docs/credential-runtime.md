# Credential helper runtime

The desktop payload pins Git Credential Manager 3.0.2 and verifies each official release archive against its SHA-256 digest. Windows x64 and Ubuntu x64 qualification uses the standalone native-AOT packages. They do not require a separately installed .NET Framework or .NET runtime. The payload inventory rejects a helper version that differs from the pin.

The native-AOT executable has no single-file `runtimeconfig.json`/`deps.json` pair. Its inventory therefore binds the exact extracted executable digest to upstream's declared .NET 10.0.14 build, recording `metadataFormat: upstream-native-aot-digest` and the release URL. This is upstream build provenance checked against the binary, not a claim that an arbitrary string extracted from an executable proves its runtime version. Both supported executable digests are checked with bounded reads before accepting that metadata. Any replacement requires a new verified pin and review. Earlier single-file and Windows framework metadata readers remain available for identifying older artifacts, but do not bypass current payload version admission.

The 3.0 platform change is compatible with the supported Windows 10-or-later and Ubuntu 24.04 x64 profiles. Observanda fixes the helper provider to GitHub, disables inherited Git/GCM configuration, uses its own credential namespace and selects the OS credential store. It does not configure the helper globally. GitHub browser authentication is separate from the new Azure authentication broker behavior.

GCM 3 sends `github list` results through its console stream. Account-list capture has a shared 64 KiB bound; credentials remain parsed from standard output alone. Error messages never include those streams. Synthetic native checks cover storing, account discovery, reopening the helper, retrieving and erasing within an isolated namespace. Ubuntu checks use a disposable Secret Service session.

Interactive sign-in uses GCM's device authorization mode. Observanda displays the one-time code and a fixed `https://github.com/login/device` link; it does not launch a loopback callback page. A separate 8 KiB rolling console buffer recognizes only the pinned helper's GitHub challenge, including wrapped lines. The device code is kept in memory and cleared after completion or cancellation. OAuth credentials are verified against GitHub's authenticated identity before being saved in the operating-system credential store. Cancelling or locking prevents a late response from replacing the account.

Destination discovery reads one page of memberships or repositories at a time. Tokens without membership access can list organization owners through their accessible repositories. Selecting a repository fills its owner, name and default branch without saving the destination. Repository permissions and organization approval are still enforced by GitHub at publication time.

The opt-in `OBSERVANDA_TEST_GITHUB_DEVICE=1` credential-helper test obtains an actual GitHub device challenge and cancels before authentication. It does not grant account access or establish full real-account, organization-policy or installed desktop acceptance.
