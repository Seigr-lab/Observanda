# Credential helper runtime

The desktop payload pins Git Credential Manager 3.0.2 and verifies each official release archive against its SHA-256 digest. Windows x64 and Ubuntu x64 qualification uses the standalone native-AOT packages. They do not require a separately installed .NET Framework or .NET runtime. The payload inventory rejects a helper version that differs from the pin.

The native-AOT executable has no single-file `runtimeconfig.json`/`deps.json` pair. Its inventory therefore binds the exact extracted executable digest to upstream's declared .NET 10.0.14 build, recording `metadataFormat: upstream-native-aot-digest` and the release URL. This is upstream build provenance checked against the binary, not a claim that an arbitrary string extracted from an executable proves its runtime version. Both supported executable digests are checked with bounded reads before accepting that metadata. Any replacement requires a new verified pin and review. Earlier single-file and Windows framework metadata readers remain available for identifying older artifacts, but do not bypass current payload version admission.

The 3.0 platform change is compatible with the supported Windows 10-or-later and Ubuntu 24.04 x64 profiles. Observanda fixes the helper provider to GitHub, disables inherited Git/GCM configuration, uses its own credential namespace and selects the OS credential store. It does not configure the helper globally. GitHub browser authentication is separate from the new Azure authentication broker behavior.

GCM 3 sends `github list` results through its console stream. Observanda accepts that stream only for account discovery; credentials remain parsed from standard output alone. Both captured streams share a 64 KiB bound, and error messages never include their contents. Synthetic native checks cover storing, account discovery, reopening the helper, retrieving and erasing within an isolated namespace. Ubuntu checks use a disposable Secret Service session. They do not authenticate a real account or establish packaged browser-sign-in acceptance.

Upstream references: [3.0 breaking changes](https://github.com/git-ecosystem/git-credential-manager/releases/tag/v3.0.0), [3.0.2 security update and runtime version](https://github.com/git-ecosystem/git-credential-manager/releases/tag/v3.0.2), [account-list command](https://github.com/git-ecosystem/git-credential-manager/blob/v3.0.2/src/GitHub/GitHubHostProvider.Commands.cs). Upstream reports that Brotli decompression is not enabled by default in earlier GCM releases; this update does not imply a reproduced credential-helper exploit.
